# MachineMandi System Interfaces

This document describes all on-chain data structures, public/external functions, events, custom errors, and integration requirements across the MachineMandi stack (Smart Contract, Backend, Firmware, and Frontend).

---

## 1. ABI Build Artifact

The canonical Application Binary Interface (ABI) for contract integration is generated by the Hardhat compilation process and located at:

```text
blockchain/artifacts/contracts/MachineMandi.sol/MachineMandi.json
```

Clients and backend services should import this JSON file or the generated TypeChain typings to interact with the deployed contract.

## 2. On-Chain Data Structures

### `Node` Struct
Represents a physical machine registered in the protocol by the contract owner.

| Field Name | Type | Description |
| :--- | :--- | :--- |
| `signer` | `address` | Public address corresponding to the device's hardware private key |
| `payout` | `address` | Destination wallet to receive native currency upon job completion |
| `serviceHash` | `bytes32` | Cryptographic hash describing machine capability, specifications, and terms |
| `price` | `uint256` | Exact native escrow amount (in wei) required to create a job |
| `minDelta` | `uint256` | Minimum telemetry difference (`postReading - preReading`) required to prove work |
| `active` | `bool` | Whether the node is currently accepting new jobs |

### `Job` Struct
Represents an escrowed task created by a buyer for a specific node.

| Field Name | Type | Category | Description |
| :--- | :--- | :--- | :--- |
| `nodeId` | `uint256` | Metadata | ID of the machine node assigned to this job |
| `buyer` | `address` | Escrow | Address of the buyer who funded the escrow |
| `amount` | `uint256` | Escrow | Escrowed payment amount held in the contract |
| `createdAt` | `uint256` | Lifecycle | Unix timestamp when the job was created |
| `deadline` | `uint256` | Lifecycle | Unix timestamp before which the job must be completed |
| `nonce` | `uint256` | Security | Unique nonce for EIP-712 replay protection |
| `status` | `uint8` | State | Status of the job (`OPEN`, `COMPLETED`, `REFUNDED`) |
| `preValue` | `uint256` | Telemetry | Initial sensor reading stored on completion (default: `0`) |
| `postValue` | `uint256` | Telemetry | Final sensor reading stored on completion (default: `0`) |
| `signer` | `address` | **Snapshot** | Snapshotted device signer address at creation |
| `payout` | `address` | **Snapshot** | Snapshotted payout receiver address at creation |
| `serviceHash` | `bytes32` | **Snapshot** | Snapshotted service specification hash at creation |
| `minDelta` | `uint256` | **Snapshot** | Snapshotted minimum required telemetry delta at creation |

> **Snapshot Rule:** Node parameters (`signer`, `payout`, `serviceHash`, `minDelta`) are immutable once a job is funded. Even if the owner deactivates the node, existing funded jobs settle according to their snapshotted terms.

### Job Status Enum Values

```solidity
uint8 public constant STATUS_OPEN = 0;       // Job created and escrow funded
uint8 public constant STATUS_COMPLETED = 1;  // Proof verified, payout settled
uint8 public constant STATUS_REFUNDED = 2;   // Deadline expired, escrow refunded to buyer
```

## 3. Public & External Contract Functions

### Administrative Methods (Owner Only)
- **`registerNode(address signer, address payout, bytes32 serviceHash, uint256 price, uint256 minDelta) returns (uint256 nodeId)`**
  Registers a new node. Reverts if `signer` or `payout` is zero address, `price` is zero, or `serviceHash` is empty.
- **`deactivateNode(uint256 nodeId)`**
  Deactivates an active node, preventing new jobs from being created. Reverts if already inactive or not found.

### Escrow & Settlement Methods (Public / Buyers / Relayers)
- **`createJob(uint256 nodeId, uint256 deadline) payable returns (uint256 jobId)`**
  Escrows native funds and creates a new job.
  - Requires `msg.value == node.price`.
  - Requires `node.active == true`.
  - Requires `deadline > block.timestamp` and `deadline <= block.timestamp + 30 days`.
- **`submitProof(uint256 jobId, uint256 nodeId, uint256 nonce, uint256 startedAt, uint256 completedAt, uint256 preReading, uint256 postReading, bytes32 serviceHash, bytes calldata signature)`**
  Submits an EIP-712 device proof. Recovers the signer and verifies all constraints against the job's snapshotted values. On success:
  - Sets `job.status = STATUS_COMPLETED`.
  - Records `preValue` and `postValue`.
  - Transfers `job.amount` to the snapshotted `payout` address.
- **`refund(uint256 jobId)`**
  Refunds expired escrow to `job.buyer`.
  - Requires `job.status == STATUS_OPEN`.
  - Requires `block.timestamp > job.deadline`.
  - Sets `job.status = STATUS_REFUNDED` before transferring funds.

### View Functions
- **`getNode(uint256 nodeId) view returns (Node memory)`**: Returns full Node struct.
- **`getJob(uint256 jobId) view returns (Job memory)`**: Returns full Job struct.
- **`owner() view returns (address)`**: Current owner address.
- **`nodeCount() view returns (uint256)`**: Total registered nodes.
- **`jobCount() view returns (uint256)`**: Total created jobs.
- **`MAX_DEADLINE_DURATION() view returns (uint256)`**: Maximum allowed job deadline duration (30 days).
- **`WORK_PROOF_TYPEHASH() view returns (bytes32)`**: EIP-712 typehash for `WorkProof`.

## 4. Contract Events

| Event Name | Signature & Parameters | Description |
| :--- | :--- | :--- |
| `NodeRegistered` | `(uint256 indexed nodeId, address indexed signer, address indexed payout, bytes32 serviceHash, uint256 price, uint256 minDelta)` | Emitted when a node is registered |
| `NodeDeactivated` | `(uint256 indexed nodeId)` | Emitted when a node is deactivated |
| `JobCreated` | `(uint256 indexed jobId, uint256 indexed nodeId, address indexed buyer, uint256 amount, uint256 deadline, uint256 nonce)` | Emitted when a job is created and funded |
| `JobRefunded` | `(uint256 indexed jobId, uint256 indexed nodeId, address indexed buyer, uint256 amount)` | Emitted when escrow is returned to buyer |
| `JobCompleted` | `(uint256 indexed jobId, uint256 indexed nodeId, address indexed buyer, address payout, uint256 amount, uint256 preReading, uint256 postReading, address recoveredSigner)` | Emitted when proof is verified and payout settled |

## 5. Custom Errors & Categories

The contract uses gas-efficient Solidity custom errors instead of revert strings:

```solidity
// Authorization
error NotOwner();

// Node Validation
error InvalidSigner();
error InvalidPayout();
error InvalidPrice();
error InvalidServiceHash();
error NodeNotFound();
error NodeNotActive();

// Escrow & Deadline
error IncorrectPayment();
error InvalidDeadline();
error DeadlineTooFar();
error DeadlineNotPassed();
error DeadlineExpired();

// Job Matching & State
error JobNotFound();
error JobNotOpen();
error JobAlreadyRefunded();
error InvalidNodeId();
error InvalidNonce();

// Work Proof Validation
error InvalidTimestamps();
error InvalidReadings();
error InsufficientDelta();

// Fund Transfer & Reentrancy
error TransferFailed();
error ReentrancyGuardReentrantCall();
```

## 6. Subsystem Integration Data Mapping

### 1. Backend / Relayer
The backend listens to blockchain events and relays proofs:
- **Tracks On-Chain**: Listens for `JobCreated` to notify physical machines of incoming work.
- **Watches**: `jobId`, `nodeId`, `nonce`, `deadline`, and `serviceHash`.
- **Relays**: Ingests `WorkProof` telemetry payload and raw `signature` from firmware; submits `submitProof(...)` transaction to RPC.
- **Monitors Expiration**: Calls `refund(jobId)` for expired jobs if requested by buyers or automated keepers.

### 2. Frontend / Dashboard
- **Node Catalog**: Reads `getNode(nodeId)` and `nodeCount` to display available machines, pricing, and specs.
- **Job Creation**: Calls `createJob(nodeId, deadline)` sending exact `node.price` as native ETH.
- **Live Status Display**: Displays job status (`OPEN`, `COMPLETED`, `REFUNDED`), creation time, deadline countdown, and sensor telemetry (`preValue`, `postValue`).
- **Refund Trigger**: Enables the buyer to execute `refund(jobId)` when countdown passes deadline and status is `OPEN`.

### 3. Hardware Firmware
- **Ingestion**: Polls backend for pending jobs matching its assigned `nodeId`.
- **Execution**: Reads hardware sensor (`preReading`), activates physical actuator/relay, reads sensor after work (`postReading`).
- **Signing**: Formats the EIP-712 payload with its exact `nodeId`, `jobId`, `nonce`, `startedAt`, `completedAt`, readings, and `serviceHash`; signs with internal hardware private key.
- **Reporting**: Posts payload + signature to backend relayer endpoint.

## 7. Verified vs. Display-Only Values

| Parameter | On-Chain Verified | Display-Only / Off-Chain |
| :--- | :---: | :---: |
| Exact Payment Amount (`price == msg.value`) | ✅ | — |
| Job Deadline (`block.timestamp <= deadline`) | ✅ | — |
| Cryptographic Signer (`recoveredSigner == snapshotted signer`) | ✅ | — |
| Telemetry Delta (`postReading - preReading >= minDelta`) | ✅ | — |
| Chronological Timestamps (`completedAt >= startedAt`) | ✅ | — |
| Nonce and Node Binding (`nonce == job.nonce`, `nodeId == job.nodeId`) | ✅ | — |
| Service Specification Hash (`serviceHash == job.serviceHash`) | ✅ | — |
| Physical Fluid Volume / Work Done in Real World | ❌ | ✅ (Reported by sensor) |
| Human-Readable Service Description | ❌ | ✅ (Resolved off-chain via serviceHash) |
| Physical Hardware Health / Location | ❌ | ✅ (Off-chain telemetry) |
